# 项目顺序

## Phase 0 — 项目蓝图
状态：完成

建立产品目标、拓扑、边界、开发规则。

## Phase 1 — 开源方案侦察
状态：下一步

目标：不写重复代码，找成熟项目作为技术参考或可集成组件。

重点：
- RSS / 新闻采集
- 多来源聚合
- 去重
- 事件聚类
- 趋势检测
- LLM 摘要
- 定时任务
- X 数据分析
- 内容表现分析

产物：
- docs/OPEN_SOURCE_MAP.md

## Phase 2 — 信息雷达最小闭环

目标：

来源 → 采集 → 标准化 → 去重 → 排序 → 今日信息

先跑通，不追求复杂 UI。

## Phase 3 — 内容机会池

目标：

今日信息 → 为什么重要 → 谁关心 → 可写角度 → 内容机会

## Phase 4 — 个人账号分析

导入用户历史推文和表现数据，建立个人化信号：

- 主题
- Hook
- 长度
- 结构
- 发布时间
- 媒体/链接
- 互动表现

输出的是经验模型，不是所谓“官方 X 权重”。

## Phase 5 — 一键推文生成

主题/机会 → 研究 → 推理 → 生成 → 去 AI 味 → 排版

这是产品核心闭环。

## Phase 6 — 移动端 MVP

最小界面：

- 输入框
- 今日机会
- 生成按钮
- 结果页
- 复制/编辑

## Phase 7 — 图片

在文字确定后再生成配图，保留图片风格偏好。

## Phase 8 — 发布与自动化

最后才考虑：
- X 发布
- 定时发布
- 每日自动报告
- 更复杂的账号增长分析

## 开发纪律

每个 Phase 拆成小 Stage。

每个 Stage 必须：
1. 有明确目标。
2. 有可验证结果。
3. 完成后立即 commit。
4. 更新 PROJECT_STATE.md。
5. 记录下一步。

禁止一次性跨越多个 Phase 大量实现。
